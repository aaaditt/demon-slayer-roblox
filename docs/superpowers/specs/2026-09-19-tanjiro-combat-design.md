# Tanjiro combat slice — design

Date: 2026-09-19 · Branch: `combat/tanjiro` (worktree off `81c5433`) · Status: approved in chat, awaiting spec review

## Goal

Make Tanjiro feel like a real Roblox battlegrounds fighter (reference feel: *Jujutsu Shenanigans*) with Demon Slayer identity: a proper R15 body and outfit, his canonical sword(s) worn on the hip with a draw, authored sword animations, a 4-hit M1 string with finisher, directional dashes, readable hit feedback, M1-only blocking and technique clashes. Tanjiro is the template; every later character copies it. Anime-grade technique VFX and the open-world redesign are separate specs (see "Out of scope").

## Design principle: kit, not character

Combat data is keyed by **sword definition + breathing style + animation set**, not by named character. A future custom slayer (see `docs/DIRECTION.md`) is just another combination of those three. Tanjiro is the first instance.

## §1 Character body (`src/server/CharacterBody.luau`, new)

- Build fighters as **R15** via `Players:CreateHumanoidModelFromDescription(description, Enum.HumanoidRigType.R15)` on the server. Locomotion (idle/walk/run/jump/fall) uses Roblox's standard R15 animations so movement reads like other Roblox games.
- Appearance comes from a per-character `appearance` record in `data/catalog.json` (source of truth; regenerated into `Content.luau`): body colors, `shirt`/`pants` asset IDs, accessory asset IDs, face decal ID.
- Tanjiro appearance:
  - Shirt/Pants textures **generated by a script** (`scripts/generate_clothing.py`, 585×559 classic templates): black Corps uniform with white leg wraps/tabi, green-and-black ichimatsu checkered haori printed over torso and arms, 滅 on the uniform back.
  - Hair: Creator Store accessory (dark red-black, short spiky); hanafuda earrings: Creator Store or a small part accessory; forehead scar: face decal. IDs recorded in `data/assets.json` with source URL and license note.
- **Fallback (required):** if an asset ID is absent or fails to load (CI, offline Studio, not yet uploaded), apply part-built equivalents to the R15 body (checker panels, hair block, earrings) so basic play never depends on external assets. This replaces the AGENTS.md "no external assets" rule with "no external assets **required** for basic play".
- Other characters remain on the current `Rig.create` blocky rig until their own pass. Both rig kinds must work with `Combat`/`Melee`; joint lookups go through a small adapter (R6 names vs R15 names).

## §2 Swords (`src/shared/Swords.luau` data + `src/server/SwordBuilder.luau`, new)

Each sword definition = blade (length, width, color, edge-line color, curvature, engraving), tsuba (shape builder id + color), tsuka (wrap color, diamond color), habaki, saya (color, hip side). Built from parts, welded; blade carries two attachments + `SwordTrail`.

Tanjiro variants (corrected 2026-09-19: the Swordsmith Village blade arrives already fitted with Rengoku's tsuba, so it is one variant, not two), selected by story progress (a `swordVariant` on the profile/story state):

| Variant | When | Blade | Tsuba | Notes |
|---|---|---|---|---|
| `urokodaki_steel` | Training (ch. 1–2) | plain steel | simple round | Urokodaki's sword |
| `tanjiro_black` | after Final Selection | black, lighter edge line | black wagon-wheel (ring + spokes) | wrap black over red diamonds; black saya |
| `tanjiro_yoriichi` | from ch. 15 (after Swordsmith Village) | black; Yoriichi's ~300-year-old blade restored by Haganezuka, 滅 engraving (verify) | Rengoku's flame tsuba (red/orange flame ring), fitted by the smiths | final look |

Note on canon: the blue "water" seen in the anime is the Water Breathing effect, not the blade colour. Replica-sourced details (wrap colours, pommel) must be checked against anime screenshots before sign-off and recorded in `docs/RESEARCH.md`.

Mounting: saya on the **left hip** (attached to `LowerTorso`, angled back ~20°), hilt forward. Drawn: hilt attaches to `RightHand` grip; saya stays on hip. Draw/sheathe transitions are driven by animation keyframe markers (`Grip`, `Release`), not timers.

## §3 Animations (`src/shared/AnimData/Tanjiro.luau`, new)

Single source of truth: keyframe tables per animation — list of `{t, pose = {JointName = CFrame}, easing}` plus named markers (`Hit`, `Grip`, `Release`, `CanChain`, `End`).

Two playback paths:
1. **Published** — `scripts/build_keyframes.py` (invoked by `scripts/check.py` during the place build) emits `KeyframeSequence` instances into `ServerStorage.AnimSources.Tanjiro`. The owner opens Studio once, publishes each via the Animation Editor, and pastes IDs into `data/animations.json`. Client plays via `Animator:LoadAnimation` and listens to `GetMarkerReachedSignal`.
2. **Code fallback** — `src/client/KeyframePlayer.luau` interpolates the same tables onto `Motor6D.Transform` and fires the same marker callbacks. Used whenever an ID is missing.

Server never trusts client markers; it runs the same timings from the data (marker times are shared), so both paths hit on identical frames.

Tanjiro animation set:

| Id | Description |
|---|---|
| `idle_sheathed`, `idle_drawn` | drawn: low mid-guard (chūdan), blade angled forward |
| `draw`, `sheathe` | quick-draw from left hip (0.35 s); sheathe with blade-flick (0.5 s) |
| `m1_1` | *kesa-giri*: diagonal downward cut, right shoulder → left hip |
| `m1_2` | *gyaku kesa*: rising reverse diagonal, left → right |
| `m1_3` | *yoko-giri*: horizontal cut, body turns into it |
| `m1_4` | finisher: step-in overhead vertical cut (*kara-take-wari*), knockback |
| `dash_f`, `dash_b`, `dash_l`, `dash_r` | low forward lunge / hop back / side slides (sword held) |
| `hit_l`, `hit_r` | light flinch alternating with the attacker's swing side |
| `knockback`, `getup` | launched fall (ragdoll-lite) and recover |
| `block` | blade horizontal, off-hand on spine of blade |
| `clash_recoil` | blades rebound, slide back |

## §4 Mechanics (`src/server/Melee.luau`, new; `Combat.luau` delegates `basic`/`guard`/`dodge` to it)

All numbers in `Config.luau` under `Melee`.

- **M1 string (4 hits):** input during `CanChain` window of the previous swing (≤0.5 s after its `End`) continues the chain; otherwise restarts at 1. Hits 1–3: 9 dmg, hitstun 0.45 s (target cannot act, WalkSpeed ×0.3). Hit 4: 14 dmg, knockback 25 studs + 0.35 s up-velocity, 0.8 s knockdown then `getup`. After hit 4: 0.9 s end lag. Attacker moves at WalkSpeed ×0.5 while swinging.
- **Hitboxes:** at the `Hit` marker time the server runs `workspace:GetPartBoundsInBox` with a box in front of the attacker (per-swing size in anim data, default 7×6×8 studs, centred 4 studs forward), filtered to actor root parts via `OverlapParams`. Each target is hit at most once per swing. Lag tolerance: box extended 1.5 studs forward; target root must be within 12 studs and in front (dot > 0.2) at server time.
- **Dashes (replace dodge):** `Q` + held WASD direction (no direction = front). Front 20 studs, side 14 studs (side dash curves around the current target if one is locked within 20 studs), back 12 studs. Cooldowns: front 2.5 s, side/back 1.5 s, separate timers. **No invulnerability** — escaping is by distance. Existing `invulnerableUntil` is no longer set by dash. Existing wall-aware `Combat:move` is reused.
- **Block:** hold `F`. From the front (dot > 0.3) it negates M1 damage and hitstun. Techniques pass through block at full damage. An M1 finisher landing on a blocker = guard break: 1.0 s stun. Existing parry (`ParryWindow` 0.18 s at block start) applies to M1s only and staggers the attacker 0.6 s.
- **Clash:** when an actor casts a technique and an enemy technique's hitbox would reach them within 0.25 s (or both technique hitboxes overlap), both casts cancel → `clash` event, both actors pushed back 10 studs, `clash_recoil`. If technique tiers differ (new `tier` field in catalog techniques, 1–3), the higher tier wins: loser takes 50% of the winner's damage, no push for the winner. Equal tiers: pure cancel.

## §5 Hit feedback (`src/client/HitFeedback.luau`, new)

On `hit` effect event (server → all clients):
- `Highlight` on the target model, FillColor white, FillTransparency 0.3→1 over 0.12 s, OutlineTransparency 1; reuse one Highlight per model (engine limit ~31 active).
- Hit-stop: attacker and target animation tracks (or KeyframePlayer) paused 0.06 s (finisher 0.12 s).
- Camera shake for the attacker and the victim only: 0.15 s, small amplitude (finisher larger).
- Slash spark at contact point: bounded-lifetime part/particle burst in the style colour; sound per hit type.
- Blocked hits: blue-white spark + block sound, no white flash. Clash: large white spark ring + clash sound on both actors.

## Testing

- Portable Luau tests (`tests/core.spec.luau`): chain-window state machine, hitbox inclusion math (front/back/range/tolerance), block direction rule, clash resolution by tier, dash distance/cooldown selection, sword variant selection by story state, animation data validity (markers ordered, `Hit` inside duration, all R15 joints named correctly).
- `scripts/check.py` validates `data/assets.json` / `data/animations.json` shape and that every Tanjiro animation id in AnimData exists.
- Studio spec: R15 Tanjiro spawns with fallback appearance when IDs are empty; sword mounted on left hip; draw attaches to RightHand.
- Honest limits: automated tests cannot judge feel, timing or look. Sign-off requires the owner playing Tanjiro in Studio; QA.md records exactly what was and was not verified.
